==================================================
3. DATABASE PROVIDER CHANGE
==================================================

The original project used SQL Server-specific EF Core migrations.

For the recommended no-Azure deployment architecture, the persistence provider has been changed to PostgreSQL using Npgsql.EntityFrameworkCore.PostgreSQL 10.0.3.

The old SQL Server migrations were removed from the deployment package because provider-specific SQL Server migrations must not be applied to PostgreSQL.

For the first deployment, Database:EnsureCreated=true creates the schema from the current EF Core model.

Future schema changes should use newly generated PostgreSQL EF Core migrations and should be applied through a controlled deployment process.

==================================================
4. PRODUCTION SECURITY CHANGES
==================================================

Production database credentials are no longer stored in appsettings.json.

Production JWT signing secret is no longer stored in appsettings.json.

CORS origins are configured through Cors__AllowedOrigins.

The frontend production API URL is configured through VITE_API_BASE_URL.

HTTPS redirection is only enabled in Development because Render terminates HTTPS at the platform edge.

Unexpected server exceptions return a generic message while retaining a TraceId for diagnostics.

==================================================
10. KNOWN DEPLOYMENT NOTE
==================================================

This package is deployment-ready for a fresh PostgreSQL database.

Because the previous database migrations were SQL Server-specific and the environment was changed to PostgreSQL, the first deployment uses EnsureCreated rather than attempting to reuse those migrations.

This is appropriate for a fresh deployment. It should not be treated as the long-term database migration strategy.
